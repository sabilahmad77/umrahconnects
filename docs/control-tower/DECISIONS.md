# Decisions — Claude core track

Each decision records the context, the choice and its consequence. The date is 2026-09-17 unless stated.

| ID | Decision | Why | Consequence |
|---|---|---|---|
| D-001 | The core track works in the worktree `/Users/macbook/Projects/umrah-connects-core-finalization` on branch `claude/core-finalization`, with its own database `umrah_connects_core`. The e2e suite uses the disposable database `umrah_connects_test`. | Codex is editing `apps/web` in its own worktree (`codex/web-frontend-finalization`), and schema migrations must not touch the main-branch development database. | Local servers for this track run on :4200 (API) and :3200 (web). Nothing is pushed. |
| D-002 | Keep the existing `namespace:resource:action` permission model, and make `src/modules/rbac/catalog.ts` its single source of truth. The catalogue is synced to the database at boot. An unknown capability on a route stops the build (typed decorator) and stops the boot. | The model already existed and was DB-driven. It was undermined by drift and by roles that did not exist. | Business names map onto catalogue keys (e.g. `users.read` → `core:user:read`, `refunds.manage` → `finance:payment:refund`). The mapping is at the top of `catalog.ts`. |
| D-003 | **Deny by default.** Every route declares `@Public`, `@RequirePermissions` or `@AnyAuthenticated`, and the guard refuses anything else. `@AnyAuthenticated` is used only where the service checks ownership. | 38 routes used to be "any logged-in user" by omission. | The API refuses to start while any route lacks a policy (`AccessPolicyCheck`). |
| D-004 | **Finance is a set of scoped capabilities, not a platform role.** `finance:invoice:*`, `finance:payment:read/process/refund` and `finance:report:read` apply inside one organization. `FINANCE_MANAGER` is a tenant role template an organization admin can grant. Platform-wide money visibility is `platform:finance:read`, held only by Super Admin. | The product has no cross-organization finance staff. Finance work belongs to each agency or provider. | No global Finance role exists. Refunds are separated from collection. |
| D-005 | **Super Admin is a platform role.** Platform accounts belong to a dedicated `PLATFORM` organization (new `TenantType`). `platform:*` capabilities count only when they come from the global `SUPER_ADMIN` role and the account belongs to that organization. Platform accounts hold no organization capabilities. | Separates platform administration from operators (AUD-002) and gives defence in depth if a grant is mis-assigned. | `syncCatalog()` removes platform capabilities from every other role. Google sign-in is refused for platform accounts. The production Super Admin is created with `bootstrap-platform-admin` (no default password). |
| D-006 | **Role codes:** `SUPER_ADMIN`, `OPERATOR_ADMIN`, `OPERATOR_STAFF`, `HOTEL_MANAGER`, `TRANSPORT_MANAGER`, `VISA_OFFICER`, `FINANCE_MANAGER`, `PILGRIM` (shown as "Traveler"). | The web maps dashboards by substring (`inferDashboardType`). `PILGRIM` keeps the traveler dashboard mapping working without a frontend change. | Legacy per-tenant "Operator Admin" rows are kept. Their holders also receive `OPERATOR_ADMIN` via `sync-rbac`. |
| D-007 | **Travelers** all share one community organization, so they hold no organization-wide read capability (`marketplace:listing:read`, `social:post:*` only). Their own data is reached through ownership checks. | Organization-wide reads there would leak other travelers' data. | Features such as "my groups" and "my visa" need traveler-scoped endpoints (XT-002, XT-003, still open). |
| D-008 | **Provider onboarding:** a verified traveler founds an organization (`OPERATOR`, `MU_ASSASA`, `VENDOR_HOTEL`, `VENDOR_TRANSPORT`, `VENDOR_VISA`). The founder moves into it with that type's admin role. The organization stays `PENDING_KYC` and can reach only onboarding routes (`@AllowPendingTenant`) until a Super Admin approves its KYC. | This gives every business role a real, auditable path (AUD-004, AUD-005, E-5). | Public `POST /tenants` is closed (AUD-008). Only platform admins create organizations directly. |
| D-009 | **Tenant isolation is enforced in the service layer**, using ownership helpers, the principal-derived tenant and cross-tenant tests. PostgreSQL RLS is deferred and the ADR is amended. | Partial RLS behind a pooled Prisma client would give false assurance. The guard rails plus tests are verifiable now. | `docs/adr/001` is amended. RLS is a later loop (LOOPS_BACKLOG). |
| D-010 | **Prisma Migrate replaces `db push`.** The baseline migration `20260917000000_baseline` was proven identical to the live schema (diff exit 0). Later changes are additive migrations. The Docker image never migrates on start. | `db push --accept-data-loss` on every boot was a data-loss path (SEC-036). | `prisma migrate deploy` is an explicit deploy step. The legacy production DB needs `migrate resolve --applied` for the baseline (KVM README §3). |
| D-011 | **Sessions:** 15-minute access JWTs (HS256, `typ=access`) re-validated against the database on every request (user status, organization status, `sessions_revoked_at`). Refresh tokens rotate, are stored as hashes, and a replayed rotated token revokes all sessions. The refresh token is also set as an httpOnly `SameSite=Lax` cookie (`__Host-` in production). | Locking a user or organization and signing out must take effect immediately (AUD-025). localStorage refresh tokens are exposed to XSS. | `AUTH_REFRESH_TOKEN_IN_BODY=true` keeps the current web client working. Setting it to `false` once the web uses the cookie is XT-R01. |
| D-012 | **Account protection:** 10 failed logins trigger a 15-minute lock (configurable). Per-IP and per-IP+email throttling on authentication routes. The login timing is the same for unknown emails and wrong passwords. | AUD-007. | The lock message only appears when the correct password is supplied. |
| D-013 | **Password reset and email verification** use random 256-bit single-use tokens, stored hashed in `otp_codes` and delivered by a `MailService` (`smtp` \| `log` in development only \| `none`). Reset revokes every session. | AUD-010, AUD-014, AUD-015. | In production without SMTP, forgot-password returns 503 rather than pretending to send. The SMTP credentials are an external blocker. |
| D-014 | **Phone OTP login is disabled** (503) until an SMS provider is integrated. The code path was hardened anyway: `crypto.randomInt`, attempt counting, and no account creation in a client-chosen organization. | No SMS provider exists. The old path could create ACTIVE users in any tenant (SEC-005). | Not a launch feature. |
| D-015 | **Google Sign-In** uses the server-side OIDC authorization-code flow with PKCE, `state` and `nonce` in a signed 10-minute httpOnly cookie. The ID token is verified by `google-auth-library`. The browser receives only a 2-minute single-use ticket (in the URL fragment) and exchanges it at `POST /auth/google/exchange`. | The client secret stays on the server and no tokens appear in URLs or logs. | Linking rules: an existing Google identity signs in. A verified Google email matching exactly one account links to it; if that account never verified its email, its password is cleared and its sessions revoked (pre-hijack defence). Otherwise a new Traveler is created. Ambiguous matches and platform accounts are refused. Google never grants more than Traveler. |
| D-016 | **Stripe** uses PaymentIntents via the official SDK. Amounts always come from the server: the invoice or booking outstanding balance, a smaller partial amount, or the listing booking total. Webhooks (signature-verified, deduplicated by event id) or a server-side retrieve are the only source of "paid". If the provider-reported amount or currency differs from the record, the payment is held as `DISPUTED`. Every Stripe call carries an idempotency key. | SEC-011, SEC-013, XT-004. | The sandbox gateway cannot exist in production. The client can no longer choose the provider. A traveler checkout (`/payments/checkout`) pays the provider's organization. |
| D-017 | **Storage:** R2 through the S3 SDK (`STORAGE_DRIVER=r2`). Documents go to a private bucket and are read via presigned GETs of at most 15 minutes. Media goes to a public bucket with a CDN domain. `local` remains for development, or for production with a persistent volume. File type is decided by magic bytes. | The repository had no R2 implementation (only S3/Cloudinary stubs). Static `/uploads` exposed passport scans (AUD-006). | `/uploads` serves only top-level public media. Private files are reached via `/documents/.../url` (audited) and signed links. Existing document URLs (`/uploads/visa-documents/...`) no longer resolve (XT-R03). |
| D-018 | **Hosting:** Hostinger KVM 8 runs Docker Compose with Caddy (automatic HTTPS), the API and PostgreSQL 16. There is no Redis, Kafka or Kubernetes. Kafka is now off by default. | These are the simplest components the application actually needs. | If the API is ever scaled horizontally, the throttler storage must move to Redis. |
| D-019 | **Render is deprecated but kept** until the KVM cutover. Its blueprint was updated to production-safe values. | Removing it now would remove the only documented deployment path before a replacement is live. | See INFRASTRUCTURE.md for the inventory. |
| D-020 | **Client IP behind the web proxy:** `X-UC-Proxy-Secret` (the shared secret) plus `x-vercel-forwarded-for` is trusted. Without the secret, the TCP or `TRUST_PROXY` address is used. | Every browser request reaches the API through Vercel's shared egress IPs, so per-IP limits would lump all users together. | The web must add the header (XT-R05). |
| D-021 | **Free-form JSON fields** in DTOs use `@RawJson()`. | The global `enableImplicitConversion` silently turned objects inside untyped arrays into `[]` (found by e2e tests: KYC documents were stored as `[[]]`). | A regression unit test covers it (`validation-pipe.spec.ts`). |
