# Cross-track requests — Claude core track → Codex web track

The backend lives on branch `claude/core-finalization`. Nothing in `apps/web` was changed by the core track. Each item below is a frontend action the new backend contract needs or enables.

## Status of Codex's backend dependencies (`docs/ui-ux/BACKEND_DEPENDENCIES.md`)

| ID | Codex dependency | Status | Contract |
|---|---|---|---|
| XT-001 | Signup must provision a role or activation state | **FIXED** | `POST /auth/register` always creates a Traveler (`roles: ["PILGRIM"]`) in the community organization. `roleInterest` is informational. Providers go through onboarding (XT-R08). |
| XT-002 | Current-user group membership | **OPEN — deferred** | No traveler-scoped group endpoint yet. Travelers cannot read organization groups (D-007). Proposed: `GET /groups/mine` (members only). |
| XT-003 | Current-user visa status | **BLOCKED — product decision** | Visa applications belong to organization pilgrim records, which are not linked to user accounts. A pilgrim↔user link, with consent, has to be designed first. |
| XT-004 | Server-authoritative marketplace pricing | **FIXED** | The server computes the total (per person × party size, per group). Other pricing models get 400 "use an inquiry or a request". A client `totalAmountCents` is only compared; a mismatch gets 400. |
| XT-005 | Persisted settings / preferences | **OPEN — deferred** | There is no preferences model. Available now: `POST /auth/change-password`, `POST /auth/logout-all`, `GET /auth/me`. |
| XT-006 | Google sign-in and email verification | **FIXED (backend)** | See XT-R06 and XT-R07. |
| XT-007 | Platform scope for `/admin` | **FIXED** | Every `/admin/*` route requires a `platform:*` capability, held only by `SUPER_ADMIN` in the PLATFORM organization. |
| XT-008 | Real accounts for every role | **FIXED (development)** | `prisma/scripts/seed-demo-roles.ts` (see OPERATOR_SETUP.md). |
| XT-009 | Local API availability | **FIXED** | API on :4100 (main) and :4200 (core worktree); ports are recorded in LOCAL_WORKSPACE_POLICY.md and LOCAL_TEST_GUIDE.md. |

## Requests to the web track

| ID | Priority | Request |
|---|---|---|
| XT-R01 | P1 | **Refresh token.** Stop storing `refreshToken` in `localStorage`. The API sets an httpOnly cookie (`uc_rt` locally, `__Host-uc_rt` in production), and `POST /auth/refresh` and `POST /auth/logout` read it when the body is empty (same-origin via `/proxy-api`). Once shipped, operations set `AUTH_REFRESH_TOKEN_IN_BODY=false`. |
| XT-R02 | P1 | **Role routing from real server roles.** `SUPER_ADMIN`→admin, `HOTEL_MANAGER`→hotel, `TRANSPORT_MANAGER`→transport, `VISA_OFFICER`→compliance, `FINANCE_MANAGER`→finance, `PILGRIM`→traveler, `OPERATOR_ADMIN`/`OPERATOR_STAFF`/legacy `Operator Admin`→operator. The current `inferDashboardType` substring logic already maps these. Use `GET /auth/me` → `permissions` (or `GET /rbac/my-permissions`) for route and UI guards (AUD-024). The API returns 403 for anything else. |
| XT-R03 | P1 | **Private documents.** Visa document files are no longer served from `/uploads/...`, and new uploads store `url: "private:<key>"`. To open a file, call `GET /documents/visa/:docId/url[?version=n]`, which returns `{ url, expiresAt }` valid for 5 minutes, then open `url`. KYC: `GET /documents/kyc/:kycId/:index/url`. |
| XT-R04 | P2 | **Quick Demo Access** (localhost only): sign each persona in with its own seeded account instead of the operator account plus a client-side `dashboardType`. With the new backend, the "Super Admin" tile gets 403 on `/admin/*` (verified in the browser). |
| XT-R05 | P1 | **Proxy headers and origin.** In `next.config.mjs`, require `API_PROXY_ORIGIN` in production (remove the `onrender.com` fallback). Add middleware for `/proxy-api/*` that sets `X-UC-Proxy-Secret` (server env `PROXY_SHARED_SECRET`) and forwards `x-vercel-forwarded-for`. Without it, every user shares Vercel's IP rate-limit bucket (D-020). |
| XT-R06 | P2 | **Google Sign-In.** Show the button only when `GET /auth/google/status` returns `enabled: true`. Button → navigate to `/proxy-api/auth/google/start?returnTo=<relative path>`. New page `/auth/callback` reads `ticket` and `returnTo` from the URL **fragment**, calls `POST /auth/google/exchange {ticket}`, then stores the session like a password login. `/login` shows friendly text for `?error=google_unavailable \| google_state \| google_failed \| google_email_unverified \| google_account_ambiguous \| google_privileged_account \| google_account_disabled \| google_already_linked`. Linking from settings: `POST /auth/google/link-intent` → navigate to `/proxy-api/auth/google/start?intent=<intent>` → returns to `/settings?linked=google`. |
| XT-R07 | P2 | **Email verification and reset.** New page `/verify-email?token=` → `POST /auth/verify-email/confirm {token}`. Show an "unverified" banner using `GET /auth/me` → `emailVerified`, with a resend button (`POST /auth/verify-email/request`). `forgot-password` may return 503 when mail is not configured; show that message. Reset tokens are single-use. Consider `Referrer-Policy: no-referrer` on `/reset-password` and `/verify-email`. |
| XT-R08 | P1 | **Provider onboarding UI.** `POST /onboarding/organization {type, name, country, slug?, email?, phone?, licenseNumber?, website?}` (types: OPERATOR, MU_ASSASA, VENDOR_HOTEL, VENDOR_TRANSPORT, VENDOR_VISA; requires a verified email) returns `{organization, role, tokens}`; replace the stored session. While the organization is pending, only `/auth/*`, `/tenants/me*`, `/documents/kyc*` and `/rbac/my-permissions` work. Other calls return 401 "Organization verification is not complete yet". KYC: `POST /documents/kyc` (multipart `file`, PDF/JPEG/PNG/WebP/HEIC/TIFF ≤ 15 MB) → `POST /tenants/me/kyc {registrySource, licenseNumber?, documents: [<returned objects>]}`. Status: `GET /tenants/me/kyc`. |
| XT-R09 | P1 | **Stripe.** `GET /payments/providers` → the active provider plus Stripe `publishableKey` and `testMode`. **Staff invoice payment:** `POST /payments/intents {invoiceId, amount?}` → `clientSecret` → Stripe.js `confirmPayment` → `POST /payments/intents/:id/confirm`, which returns `PROCESSING` until Stripe reports success (poll `GET /payments/:id`). **Traveler checkout:** `POST /payments/checkout {listingBookingId}` → Stripe Elements → poll `GET /payments/checkout/:paymentId`. Sandbox (development only): `POST /payments/checkout/:id/sandbox-complete`. Never show "paid" from the browser result alone. |
| XT-R10 | P1 | **Request-contract changes from the remediation** (all return 400 on unknown fields): (a) listing booking create no longer takes `status`, `paymentStatus` or `currency`, and the "payment status" and PAID/REFUNDED status options in the listing bookings tab must go; (b) `vendorId` on listing create must be the caller's own vendor; (c) new invoices always start `DRAFT` and must be issued before a payment intent is accepted; (d) refunds of gateway payments use `POST /payments/:id/refund` — `POST /finance/payments/:id/refund` rejects them; (e) deciding a visa (APPROVED/REJECTED) through `PUT /compliance/visas/:id` needs `visa:application:manage`; (f) `POST /tenants` is platform-only; (g) `GET /tenants/slug/:slug` returns only `{id,name,slug}` for active organizations; (h) `/inquiries` (list/update) is platform-only; (i) groups, social and connections return 404 for records the caller may not see; (j) hotel booking, room, allotment and transport payloads are strictly validated (enums, non-negative amounts, UUIDs); room/seat counters are server-owned; (k) `POST /payments/intents` requires `invoiceId` or `bookingId`. Full per-module lists are in RELEASE_EVIDENCE.md. |
| XT-R11 | P2 | **R2 media.** Public media URLs become absolute (`S3_PUBLIC_BASE_URL/media/...`) when `STORAGE_DRIVER=r2`. Add that host to `images.remotePatterns`. Also fix the wrong `umrahconnects.io` image domain (AUD-031). |
| XT-R12 | P2 | Add `PLATFORM` to the tenant-type labels in `lib/statuses.ts`. The admin tenant list includes the platform organization. |
| XT-R13 | P3 | Settings: "Change password" → `POST /auth/change-password {currentPassword, newPassword}`; "Sign out everywhere" → `POST /auth/logout-all`. |
| XT-R14 | P3 | Password policy changed to 8–128 characters with at least one letter and one digit. Update signup/reset hints. |
