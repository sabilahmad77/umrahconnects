Evidence points to browser captures and full DOM/AX checks in [final-route-checks.json](acceptance-evidence/final-route-checks.json).

PASS means the listed check was observed and met the frontend baseline. PARTIAL in Loading/Empty/Error means the implementation has a state handler but that independent state was not forced on that route; source wiring alone is not a runtime PASS. NOT APPLICABLE is static content/non-protected public routing. BACKEND BLOCKED is a correctly represented unavailable feature/configuration; route visuals can still PASS. PARTIAL route statuses retain positive fixture or form-submission coverage gaps. No row claims successful payment, OAuth, delivered email, credential change or KYC approval.

Route statuses: {'PASS': 63, 'BACKEND BLOCKED': 8, 'PARTIAL': 11}. No FAIL routes in the observed frontend baseline. Supplemental real role checks include staff, unverified signup and Operator-owned provider details.
