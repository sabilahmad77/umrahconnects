# Route UI completion matrix

79 actual source route families; 237 final production-build browser checks. Dynamic fixtures come from observed real API links. `/requests/[id]` uses an intentional missing UUID because no positive fixture was available. Resource articles share a route template; one existing article was checked, not every content variant.

Completion describes the implemented frontend disposition. Status describes acceptance evidence. COMPLETE does not mean every server transaction or role permission passed. PASS requires appropriate actual content/navigation or behavior. Protected route viewport cells remain PARTIAL because the walkthrough used one legitimate operator account and did not submit domain writes. Super Admin screens are BLOCKED for positive acceptance; their operator-denied UX is verified.

Loading/empty/error PARTIAL means implemented and inspected, with shared semantic tests, but not forced independently for every endpoint. Accessibility PARTIAL means rendered names/associations and common focus behavior verified, without full role/form/screen-reader coverage. Public inquiry submission, account creation, password changes and financial transactions were not executed. No synthetic personas or fake JWTs were used.

## Route-specific limits

- `/login` — Existing operator login/logout, password visibility, invalid-email recovery and protected record return verified. Multi-tenant selection/refresh failure not fully exercised.
