# Current accessibility baseline

Baseline PASS for observed frontend states. Latest DOM checks report no unnamed buttons/inputs. Manual review covers headings, visible labels, icon controls, image alternatives, actionable error/denied states, keyboard navigation, focus styling and mobile controls. Login has one meaningful h1 on mobile; profile and invoice section headings follow h1 with h2. Visa inboxes use the shared Radix tab component; ArrowRight focuses and selects Marketplace demand. Booking dialog keeps Tab focus inside, Escape closes, and focus returns to New Booking. Social save controls expose names and pressed state. Read-only staff invoice access hides Edit and payment collection controls.

[Interaction proof](acceptance-evidence/interaction-checks.json), [read-only invoice](acceptance-evidence/read-only-invoice-controls.txt), route AX/DOM records and mobile/native screenshots provide evidence. Persistent form labels and inline alerts are used on current auth/onboarding forms. Password controls have explicit accessible names; no new password was entered during browser QA.

The established deep-green/ivory/gold token system and focus styles are preserved. Previous token contrast analysis remains relevant to unchanged colors; actual screenshots were checked for readable critical text and visible controls. This is not an exhaustive computed contrast/touch-target measurement for every possible state. Public navigation and controls remain usable at 360px; shared button targets and dialog focus semantics retain existing component tests.

Remaining qualification: full screen-reader audit, exhaustive WCAG 2.2 AA contrast/zoom/target-size certification, all exceptional dynamic states and the missing approved hero image. These are not reported as completed tests or certification. No observed release-critical baseline defect remains in the checked states.
